# LOOP — Campus Lost & Found Portal

Responsive lost-and-found app with accounts, item posts, image uploads, matching suggestions, ownership claims, notifications, and administrator review. The backend uses MongoDB Atlas; `render.yaml` is prepared for a free Render web service.

## Deploy free
1. Create a free MongoDB Atlas cluster, database user, and network access rule. Copy the application's MongoDB connection string; replace `<password>` with the database user's password and use database name `loop_lost_found`.
2. Put this project in a GitHub repository (do not upload `.env`, `node_modules`, or credentials), then connect that repository to Render and create a Blueprint from `render.yaml`.
3. In Render's service environment settings, set `MONGODB_URI`, `ADMIN_NAME`, `ADMIN_EMAIL`, and a unique `ADMIN_PASSWORD` of at least 12 characters. `JWT_SECRET` is generated by the blueprint.
4. Deploy. The app creates its collections and indexes automatically. Check `/api/health` for `{ "ok": true, "database": "connected" }`.

The free Render web service sleeps after 15 minutes idle and can take about a minute to wake. Atlas's free cluster has a 512 MB storage limit and can pause after 30 days with no connections. Uploaded images need Cloudinary credentials for persistent storage; without them they use local disk, which Render may clear during restart or redeploy.

## Local run
1. Install Node.js 20+ and copy `.env.example` to `.env`.
2. Set `MONGODB_URI` and a long random `JWT_SECRET`, then set `ADMIN_NAME`, `ADMIN_EMAIL`, and a unique `ADMIN_PASSWORD` of at least 12 characters.
3. Run `npm ci`, `npm run admin` once, then `npm start`; open `http://localhost:5000`.

SMTP email is optional. Configure the `SMTP_*` variables to enable it.
